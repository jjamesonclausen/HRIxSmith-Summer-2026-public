# Project Timeline

### Project Goals:
*Prioritize the design goal.
1) Design a vertical axis wind turbine to capitalize on underused wind resources in an urban (or suburban) location in the Boston area (potentially the BOS airport). Should be economically feasible (in terms of power generation and production cost).
2) Learn about the engineering process and how different AI tools can be integrated. Record our experiences working with these tools and where we found them to be helpful or not. Provide documentation of our process that will assist future students in using these tools.

### Final Deliverable:
A final report detailing the design process and results, as well as AI tool reflections.

### Minimum viable plan
1. choose one concept
2. build one baseline model
3. build one alternate model (variation)
4. simulate both
5. select one final design
6. write the report

## 5 Week Work Plan

### Standing structure each week

- Each work week runs from Wednesday through Tuesday.
- Daily `9 AM` professor meeting: review blockers, confirm priorities, and assign next actions.
- Tuesday afternoon HRI meeting: use it as the end-of-week technical review and help session.
- End of each day: update design notes, simulation log, AI tool notes, and decisions while they are still fresh.

### Week 1 `07/09/2026` to `07/14/2026` - lock scope and choose the concept

Goals and measurable outcomes for the week:
- Design requirements sheet completed.
- Concept comparison matrix completed.
- One primary concept selected.
- One fallback concept defined or explicitly ruled out.
- Week 2 geometry plan written down.

Manageable tasks:
- Turn the Boston-area site and wind information into a one-page requirements sheet.
- Define the decision criteria: energy capture at low-to-moderate wind speeds, urban suitability, manufacturability, cost realism, and simulation feasibility.
- Compare the candidate VAWT concepts against those criteria.
- Record the reasons each concept is kept or eliminated.
- Choose the primary concept and identify the fallback plan.
- Define the first-pass geometry variables to set in Week 2.

Things the LLM can help with:
- Turn notes and source material into a requirements summary.
- Build a concept comparison matrix and weighted decision rubric.
- Draft meeting agendas and question lists for the professor and HRI.
- Help document why the selected concept fits the project goals better than the rejected ones.

### Week 2 (`07/15/2026` to `07/21/2026`) - build the baseline model and simulation setup

Goals and measurable outcomes for the week:
- Baseline 3D model completed.
- Baseline geometry parameter table completed.
- First SimScale setup created.
- At least one initial simulation or dry run completed.
- Key setup risks and next fixes documented.

Manageable tasks:
- Set the baseline geometry: height, diameter, blade count, blade shape or airfoil, supports, and major dimensions.
- Build and clean the baseline 3D model in Zoo Design Studio.
- Export the geometry for simulation.
- Create the first SimScale project with domain, rotating region, boundary conditions, and target outputs.
- Run an initial trial case and note any setup or meshing problems.
- Revise geometry or setup only where needed to make the baseline runnable.

Things the LLM can help with:
- Create CAD and CFD setup checklists.
- Summarize simulation best practices from the existing wiki.
- Help organize assumptions, parameter tables, and run logs.
- Help write concise updates for HRI and professor meetings.

### Week 3 (`07/22/2026` to `07/28/2026`) - compare baseline and alternate designs

Goals and measurable outcomes for the week:
- Baseline model simulated.
- Alternate model built and simulated.
- Comparison table completed.
- Preferred design direction identified.
- Week 4 refinement priorities listed.

Manageable tasks:
- Define the alternate model or variation based on the fallback plan or the most promising design change.
- Build the alternate CAD model.
- Run the main simulation cases for the baseline and alternate designs.
- Compare outputs such as startup behavior assumptions, torque or power trends, and overall feasibility.
- Identify whether one design is clearly better or whether one more small iteration is needed.
- Capture the logic behind the comparison so it can be reused in the final report.

Things the LLM can help with:
- Help structure the comparison table for the two designs.
- Draft summaries of what each simulation run showed.
- Highlight inconsistencies, missing evidence, and open technical questions.
- Help turn raw notes into a clean decision memo.

### Week 4 (`07/29/2026` to `08/04/2026`) - refine and freeze the final design

Goals and measurable outcomes for the week:
- Final design geometry frozen.
- Confirmation simulations completed.
- Energy-feasibility summary drafted.
- Rough cost or manufacturability assessment drafted.
- Report figures and tables identified.

Manageable tasks:
- Refine the selected geometry based on Week 3 results.
- Run confirmation simulations on the selected design.
- Estimate likely energy-generation performance for the Boston-area wind context using the available data and the defensible simulation story.
- Build a rough production or manufacturability assessment.
- Summarize the main technical uncertainties that remain.
- Freeze the final design so Week 5 is focused on reporting rather than redesign.

Things the LLM can help with:
- Help synthesize simulation results into a clear design rationale.
- Draft uncertainty statements that separate evidence from inference.
- Help structure the economic-feasibility discussion.
- Help outline the final report sections and assign needed exhibits.

### Week 5 (`08/05/2026` to `08/11/2026`) - finalize the design package and transition into delivery

Goals and measurable outcomes for the week:
- Final design decision and rationale clearly documented.
- Final technical figures and appendices completed.
- AI tools reflection notes drafted.
- Final report outline and evidence package completed.
- Presentation content and final documentation needs identified.

Manageable tasks:
- Assemble the final technical package: selected geometry, comparison tables, simulation results, feasibility notes, and decision rationale.
- Finish any last confirmation plots, screenshots, or tables needed for the report and presentation.
- Draft the AI reflection points covering Zoo Design Studio, SimScale AI features, the wiki, and LLM support.
- Build the final report outline and map evidence into each section.
- Review the project record for unsupported claims, missing assumptions, and documentation gaps.
- Decide what must be finished during the final documentation window from `08/12` to `08/14`.

Things the LLM can help with:
- Turn technical notes into clean report-ready summaries.
- Check whether claims are supported by the notes and simulations.
- Help compare tool strengths, weaknesses, and failure cases.
- Help organize the presentation story and final documentation checklist.

### Final Documentation Window (`08/12/2026` to `08/14/2026`)

Goals and measurable outcomes for these final days:
- Final report completed.
- AI tools reflection completed.
- Final presentation completed.
- Reusable project documentation prepared for future students.
- Submission package reviewed for clarity, completeness, and honesty about uncertainty.

Manageable tasks:
- Write and revise the full final report.
- Turn the drafted AI reflection notes into a finished section.
- Build and rehearse the final presentation.
- Make sure figures, appendices, and citations are in their final form.
- Do a final review for unsupported claims, unclear logic, and open assumptions.
- Prepare the final submission package.

Things the LLM can help with:
- Turn outline material into clean report prose.
- Tighten language around uncertainty, assumptions, and evidence.
- Help structure the presentation slides and speaker flow.
- Edit the final document for clarity, consistency, and concision.
